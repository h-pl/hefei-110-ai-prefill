# Moss / 接警预填警单工作台

React + TypeScript + Vite、shadcn/ui（Radix）、Sora + MiSans。网页预览：http://127.0.0.1:5173/ 。交互规则同步到当前Figma独立草稿与原飞书PRD。

```sh
cd form-demo
npm ci
npm run dev -- --port 5173
```

## 当前体验

1. 初始空白且不显示录音中，点击实时转写右侧播放图标开始。
2. 10句对话按接警员/报警人两路独立并行流式出现；空字段用浅灰文字扫光表现提取过程，结果逐字段、逐字流入，追问随原话更新。
3. 可暂停、继续、重播；播放开始后录音标签持续显示。刷新保留进度并暂停，顶部重置恢复空白。
4. 普通输入失焦保存；地点下拉提供12个模拟候选，选中即确认。AI原填地点与号码有独立确认按钮，手输修改需重新确认。
5. 人工值不会被后续提取覆盖，新信息只成为建议。常规提交有阻断时在字段右上角说明原因，无阻断直接提交。

## 验证与边界

`npm run build`、`npm run test`：54项规则测试通过。已实际操作初始/播放/思考动画/逐字段写入/暂停继续/10句结束/重播/刷新暂停/重置。历史`browser-checks.js`针对已被替代的填满示例入口，不能作为当前播放流程的验收脚本。

本地规则与虚构对话演示，没有实际音频或麦克风采集，也没有真实AI、地点库或调度接口。v3浏览器暂存保留播放进度，旧v1/v2键未删除。GitHub 与 Vercel 部署方式见根目录 README。

点击“采纳建议”即完成该版本的人工核对，地点/号码也无需二次确认，保留AI来源与人工保护。


## 2026-09-17 确认与移交后补充闭环

整单确认仅在“预填警单”标题旁显示绿色“已确认”，表单底部不显示完成卡。标识属于当前内容版本，草稿变化后不沿用。正常提交固定快照并显示回执；紧急移交保留未确认事项，接收、签收、派警相互独立。

返回警单继续补充 → 新对话或人工修改 → 采纳新建议/保存修改 → 右上角“发送补充（N项）” → 核对本次变化 → 关联原警情接收。没有变化时隐藏发送补充；待处理建议、未保存编辑和错误阻断发送；手输改变地点或号码后重新确认。取消核对保留草稿，成功接收的补充成为下次差异比较基线，原移交快照始终保留。

模拟服务支持成功、明确失败、结果未知，可在“交互演示”中选择。明确失败沿用原请求重试；内容更改使用新版本；未知只查询原请求。刷新中的请求恢复为未知后查询。保存记录成功才完成本轮整理；未发送重要补充、未处理建议或存储失败不能完成。没有日志列表、检索或分析入口。

本地浏览器持久化和模拟回执已实现；真实后端、权限、接收/签收/派警接口仍待接入。验证：构建通过，54项规则测试通过；浏览器走通提交、返回编辑、模拟新对话、采纳两项、发送补充和保存完成。
